## 1. 这个闭环是什么

无人值守的产品迭代循环，每轮固定六步：

```
① 从真实评测数据里找一个可证伪的问题
② 写死决策规则，再设计带权衡的方案
③ 实施（产品代码优先，最小改动）
④ 补回归测试 → 跑门禁（全绿才算过）
⑤ 落台账（证据 / 未做项 / 阻塞原因，必须如实）
⑥ 提交并推送 → 立刻进入下一轮
```

**停止条件**只有三个：台账无待办且门禁全绿；用户明确暂停/改范围；出现必须用户或外部方解决的阻塞。
上下文快满、跑完一批、写完报告——都**不是**停止条件。

### 三条硬红线（违反即不合格）

| 红线 | 含义 |
|---|---|
| 不许改测试凑绿 | 测试失败只能改产品代码；禁止删测试、弱化断言、放宽容差 |
| 不许把未做写成已完成 | 状态必须区分：已执行且验证 / 部分完成 / 范围调整未执行 / 条件阻塞 / 原计划可选未执行 |
| 不许缩减原验收条件 | 可以改实现路径，不能把原目标砍小后宣布完成 |

## 4. 一轮的标准流程（SOP）

1. **看状态**：`node scripts/loop-status.mjs`；读台账 pending/blocked；读最近 3 条 PROGRESS 小节。
2. **选问题**：必须来自**真实评测数据**（不是猜测）。写下"哪条数据、差在哪、怎么算修好"。
3. **先写决策规则**：例如"采纳需同时满足 A 且不劣于 B − 0.1"，**规则写在跑数据之前**。
4. **设计权衡**：至少列出被放弃的方案与原因（延迟/成本/口径/回滚难度）。
5. **实施**：最小改动；新增行为用环境变量开关（默认关或默认安全）。
6. **补测试**：红灯优先——先写会失败的测试，再改产品。测试要断言**行为**，不是断言实现细节。
7. **跑门禁**：`baseline_run.py --groups core`，全绿。失败只改产品。
8. **落台账**：`done` + 证据（数字/产物路径），或 `block` + 具体外部依赖。未做项单列。
9. **提交推送**：`node scripts/git-round.mjs -m "..."`，并在 push 后核对 `origin/main` 与 HEAD 一致。
10. **立刻下一轮**。若上下文将尽，把"下一条要做什么"写进 PROGRESS 再停。

### 证据写法（好 vs 差）

```
差：已优化性能。
好：文章快照 4 篇 3270 字，嵌入 1 篇 ~8.7s → 3 篇 ~25.9s（线性），缓存命中 17ms；
    产物 benchmarks/results/xxx_20261027-1lxzsy.json；未做：冷启动预热常驻方案。
```

## 5. 门禁

- 入口（SM-00 起，v2 runner）：`baseline_run.py --repo <仓库> --python <主解释器> --parser-python <解析解释器> --run-root <隔离根> --expect-sha <提交> --groups "core,heavy,corpus" --tag <唯一标签>`
- v2 契约：未知分组/空清单/清单外或重复脚本/缺脚本/解释器不存在/非预期 SHA/脏树未声明/旧产物复用/生产地址变量，**一律在执行前非零拒绝**；存储全部落到 `<run-root>/iso/<tag>/`（不同 run root 完全隔离）；exit 0 但无统计行按失败处理（`no_stat_line`）；产物记录仓库、SHA、清单哈希、解释器版本与逐脚本明细。旧入口保留在 `baseline_run_legacy.py`（仅限主工作区独占隔离目录时回退使用）。
- 清单冻结在 runner 内：core 58（含 `test_git_round_allowlist.py`）/ heavy 17 / corpus 8 / infra 2（工作区层 `scratch/sm-loop/tests/`，契约测试 runner 与台账工具）。
- 新增回归测试后**必须把它加进 runner 的清单**，否则等于没进门禁。
- **当前已知基线红项（2026-11-07 基线，确定性复现，非环境抖动）**：heavy 组 5 个——`test_employee_agent`(13/14)、`test_emergency_fastpath`(29/30)、`test_chat_tool_evidence`(6/15)、`test_eval_gate_endpoint`(7/9)、`test_e2e_gate`(35/37)。已拆入台账待修；门禁在红项清零前整体退出非零，新改动以"不新增失败 + 已知红项一致"为对照口径。
- 门禁里有两类测试，别混：
  - **行为测试**：构造假客户端/临时目录，断言输出（绝大多数）
  - **契约/源码测试**：用源码字符串断言"某个写法必须存在"（如 `test_tool_partial_answer.py`）。
    改这类代码时会被卡住——这是**故意的**，说明该写法是契约。改代码保留该写法，或**先**改契约测试并说明理由。
- 门禁超时/环境坑：`PROMETHEUS_PORT=0`（Windows 保留端口段 9011–9110 会 `WinError 10013`）。

## 6. 评测工具箱（`SafetyMind/benchmarks/`）

| 脚本 | 回答什么问题 | 关键产物 |
|---|---|---|

| `eval_kb_expansion*.py` / `eval_kb_checklist_ab.py` | 知识库扩容与注入口径的收益/代价 | `results/kb_*.json` |
| `eval_corpus_gate_ab.py` | 资料库词面闸门的准确率/安全率 | `results/corpus_gate_ab_*.json` |
| `eval_model_swap_ab.py` / `eval_model_latency.py` | 换模型的质量与延迟权衡 | `results/model_*.json` |
| `bench_embedding.py` / `bench_retrieval_latency.py` | 嵌入吞吐、检索 p50/p95 | `results/bench_*.json` |
| `eval_truncation_budget.py` | 输出上限与截断/答题完整度 | `results/truncation_*.json` |

**评测三条纪律**（都是用错误换来的）：

1. **控温**：A/B 必须设 `SAFETYMIND_TEMPERATURE=0`。同一改动不控温能得出相反结论（实测 accuracy −0.267 vs +0.133）。
2. **限速**：批量判分要退避 + 节奏（429 指数退避 + 0.4s 间隔）。曾出现 36 条答案全好、72 次判分全 FAIL，
   被误读成"产品失败"，实为中继限流。
3. **控臂**：多臂实验**每臂独立进程**。用 `importlib.reload(api.main)` 切臂会让整臂答案退化成错误文案。

## 7. 安全与隐私红线

- 仓库是 **public**。凭据只从 `.env`（已 gitignore）读，唯一入口 `benchmarks/_creds.py`；
  **禁止** `os.getenv(name, "<真实值>")`、禁止 `default_key` 字段。
- 提交前守卫：`node scripts/git-round.mjs --check`（扫**全部已跟踪文件**，不是只扫本次变更）。
  规则单一事实源：`scripts/secret-patterns.json`（11 类）+ `scripts/privacy-patterns.json`（7 类）。
  加规则改 JSON 并补 `tests/test_git_guard.py`。
- 测试文件/文档里的密钥样例**运行时拼接**，不留字面量。
- **泄露后处置 ≠ 删代码**：轮换凭据 → 清历史（`filter-branch` + force-push）→ 联系 GitHub Support
  清服务端缓存对象（force-push 不删旧对象，实测仍可 raw 下载）→ 把告警标 Resolved。

## 8. 已知坑清单（踩过的，按类型）

| 坑 | 症状 | 处置 |
|---|---|---|
| 本机 DNS 偶发失败 | `ssh: Could not resolve hostname github.com` / HF 下载失败 | 重试；`git-round.mjs` 内置 3 次重试，失败退非 0 |
| 中继限流 | 大批判分全 FAIL | 429 退避 + 节奏；分离"端点故障"与"产品失败" |
| 端点抖动 | 一次跑出 9/24 `agent_error` | 先探活 3 次（应 200），再决定是否把数据当结论 |
| `importlib.reload(api.main)` | 整臂答案退化成 20 字错误文案 | 多臂实验用独立进程 |
| 工具预算耗尽 | 答案只有"工具调用未在预算内完成…" | 轮次耗尽+无正文时有一次性收尾调用；**调用数**耗尽仍按契约不追加 |
| Windows 保留端口 | `WinError 10013`，应用启动失败 | `PROMETHEUS_PORT=0`；监控绑定失败已降级不崩 |
| PowerShell 写文件带 BOM | `ast.parse` 报 `U+FEFF` | 用 `[System.IO.File]::WriteAllText` + `UTF8Encoding($false)` |
| Chroma 共享目录 | HNSW 段损坏/等锁 | 测试与评测一律用隔离目录（`*_test`、`scratch/.../iso/`） |
| D 盘空间 | 写入失败 `not enough space` | 只清理自己产生的 `scratch/` 与评测隔离库；别人目录不动 |
| 并发会话 | 同一仓库另一个 agent 也在改 | 动手前 `git status`；不强推覆盖；提交前先 fetch |
| 判分模型返回空 | 裁判静默空内容 | 判分请求必须带 `reasoning_effort: "none"` |
