# SafetyMind 意图识别基准与评测报告

> 版本：2026-09-27 ｜ 全部数字可由 `benchmarks/intent/` 中的数据集与脚本复现
> 数据集、脚本、逐条预测均随仓库发布；模型权重从 HuggingFace 拉取（bge-base/large-zh-v1.5）；标注协议为人机协同（GLM 初标 + 五模型交叉审计），人工盲测工具包见 benchmarks/intent/blind_test/

## 1. 一句话结论

**零训练的语义原型分类器（bge 双模型集成）在 19 类安全生产意图上达到 96.42%（测试集 n=1033）/ 94.88%（独立留出集 n=410），较关键词基线 +40pp，较 LLM 融合 +32pp，单条意图 13ms（GPU）——同时是准确率与延迟的最优解。（2026-09-26 独立复测逐字复现：dev 97.71 / test 96.42 / test2 94.88）**

## 2. 数据集

| 集合 | 条数 | 用途 | 构建方式 |
|---|---|---|---|
| dev | 1003 | 示例库迭代、阈值与集成权重搜索 | GLM 设计框架×槽位组合 + 手写对比示例 + 程序 QC |
| test | 1033 | 最终评测 | 同上，与 dev 分层切分、跨集近重聚类控制 |
| test2 | 数据文件 417，评测 410 | 独立复测（冠军定型后生成） | 第二批全新框架；7 条生成残留/歧义项（5 条句首 "." 工艺残留 + 2 条检查类目歧义近重）在评测脚本中显式剔除；按全文件 417 条计算为 93.53%，剔除后 94.88%——剔除理由为数据质量，但方向对成绩有利，此处如实双口径披露 |

- **19 类意图 + 4 级紧急度**；三档难度（规范表述 47% / 口语改写 31% / 边界易混 22%）
- **五模型一致性审计**：bge-large/base/gte/laya/pattern 一致分歧标记 → 逐条裁决 → 删除歧义 12 条、修正误标 7 条，**标注噪声率 0.9%**
- 诚实声明：标签为 AI 自标注（GLM 生成与审计），未做人工抽检；dev 经 4 轮错误驱动示例迭代，dev 与 test2 间约 4pp 差距即选择偏差量级

## 3. 主结果（审计后 test 集，n=1033，同口径）

| 意图引擎 | 准确率 | 延迟 p50（CPU / GPU） | 备注 |
|---|---|---|---|
| **bge large+base 原型集成（本方案）** | **96.42%** | 94ms / 13ms | 零训练，213 条原型示例库 |
| LLM 三路融合 | 64.57% | 2047ms / — | IntentRecognizer 真实路径 |
| pattern 关键词（原基线） | 56.53% | <1ms | 词表匹配 |
| Laya 判别式路由（中文短键） | 55.57% | 305ms / 57.5ms | mmBERT 生成式判别 |
| 两级终判（bge top-5 → LLM 终判） | 77.57%（dev 段 79.0%） | 4890ms | shortlist 命中率 83.1% 为理论上限 |

分档（冠军，test）：canonical 97.4% / paraphrase 93.6% / near_miss（设计出的易混边界）81.3%

## 4. 延迟实测（单条查询，服务路径）

| 引擎 | CPU p50 | GPU p50（RTX 3050Ti） |
|---|---|---|
| LLM 三路融合（glm-4-flash） | 2047ms（p95 8109ms，含 529 重试） | — |
| laya | 305ms | 57.5ms |
| bge-base + 原型 | 39.2ms | 6.9ms |
| bge-large + 原型 | 93.4ms | 13.3ms |
| **bge 双模型集成** | **~133ms** | **~20ms** |

端到端 /chat 剖析：意图换 bge（-2.9s）、RAG 重排从 LLM 换 bge 余弦（-1.5s~150s 且消除 529 重试风暴）、查询改写与意图并行（延迟移出关键路径）后，**非生成阶段从"秒级不可预测"降为"~360ms 确定性"**；剩余大头为回答生成本身（回答端点 TTFT 0.5s~40s 波动，属端点容量问题）。

## 6. 复现

```bash
# 数据集与脚本见 benchmarks/intent/
python benchmarks/intent/build_dataset.py     # 重建数据集（含 QC 与审计）
python benchmarks/intent/eval_prototype.py    # 冠军配置评测
python benchmarks/intent/eval_baselines.py    # pattern / laya / LLM 基线
```

模型：`BAAI/bge-base-zh-v1.5` + `BAAI/bge-large-zh-v1.5`（集成权重 0.5/0.5，softmax τ=0.03）；原型 = 每类 [中文短描述, 类定义, ≤3 模板, 手写示例] 的嵌入均值。

## 7. 边界
(内容见下)

- 标签为 AI 自标注（GLM 生成 + 五模型审计，噪声率 0.9%），未做人工盲测——跨数据集外推前建议人工抽检
- 测试集被触碰 3 次（冠军迭代）、test2 触碰 2 次；协议与触碰记录见 meta
- 评测条件：LLM 基线为 glm-4-flash-250414（经开放平台 Anthropic 兼容端点接入）；**更强 LLM 的对照已于 2026-10-25 补齐，见第 9 节**

## 8. RAG 检索质量：BGE 嵌入升级实测（2026-09-25）

嵌入式模式原用 n-gram 词面向量（中文语义弱）。升级为 `BAAI/bge-base-zh-v1.5` 语义嵌入后，
对默认知识库 7 篇文档、7 条定向查询（每题唯一相关文档）实测：

| 嵌入函数 | top3 命中 | top1 正确 |
|---|---|---|
| n-gram 词面（原） | 4/7（57.1%） | 2/7 |
| **BGE 语义（新，默认启用）** | **7/7（100%）** | **7/7** |

> 另：**真实业务语料**（simple_vector_rag 独立索引，n=1698 条企业隐患排查依据与工作清单）7 条定向查询：BGE 直连 top3 命中 **7/7**，n-gram 词面仅 **1-2/7**。README 所引"1-2/7"即此口径。

结论：RAG 嵌入侧的 n-gram 边界**已由 BGE 语义嵌入修复**（零 API 成本，本地推理）。
`SAFETYMIND_EMBEDDING=auto|bge|ngram` 可切换；auto 为默认（bge 可用即用，缺失回退 n-gram），
切换嵌入后集合名以 `_bge` 后缀隔离，默认文档自动重新播种。

## 9. 强 LLM 意图识别对照组（2026-10-25 补齐此前"未测"的缺口）

### 9.1 为什么要补

本文第 7 节原先承认"更强 LLM 的对照未测"，而被引用的 LLM 基线是 `glm-4-flash`（64.57%）。
这带来一个公平性质疑：**96.42% 的优势会不会只是因为对照组用了弱模型？**

本组用当前可用的强模型做**零样本**意图分类，在**同一测试集（test2 剔除后 410 条）、同一 19 类目、
同一 top-1 判分口径**下正面对比。脚本 `benchmarks/intent/eval_strong_llm.py` 可复跑，逐条预测落盘。

### 9.2 结果（test2，n=410，CPU 测延迟）

| 意图引擎 | 准确率 | macro_recall | 延迟 p50 | 备注 |
|---|---|---|---|---|
| **bge large+base 原型集成** | **94.88%** | 93.83% | **390ms** | 零训练，213 条原型 |
| **bge-base 单模** | **92.93%** | 91.37% | **141ms** | 2G 内存形态 |
| qwen-max 零样本 | 88.05% | 81.89% | 562ms | 阿里云百炼，Anthropic 兼容端点 |
| glm-4.6 零样本 | 86.59% | 77.81% | 1094ms | 智谱 bigmodel，Anthropic 兼容端点 |
| LLM 三路融合（旧基线） | 64.57% | — | 2047ms | IntentRecognizer 真实路径 |

### 9.3 结论（如实、克制）

> **本节 2026-10-25 晚已修订。上一版把 `glm-4.6`（智谱 2025 年模型）当作"强模型"，
> 据此得出"bge 胜过强模型"的结论。这个前提是错的——glm-4.6 不是前沿模型。
> 用过期模型当对照组等于自己给自己造有利结论，属方法论错误。以下是改用真前沿模型后的重测。**

真前沿模型（DeepSeek-V4.1-Flash / GLM-5.3-Flash 等）实测见第 10 节。核心结论改为：

1. **"强模型一定比 bge 强"在零样本直接分类这个任务形态上并不成立**：真前沿模型零样本分类
   准确率仍低于 bge 原型集成（具体数字见第 10 节），但差距已比旧 glm-4-flash 基线（64.57%）收窄很多。
2. **但"要不要保留意图层"是另一个问题**：意图层的价值不只是准确率，更是**确定性、延迟与成本**。
   第 10 节给出 token 实测：单次分类约 400+75 token，这个量级下"省 token"不是否定理由。
3. **真正该保留意图层的理由**（第 10 节详述）：它是**可审计、可复现、可离线**的路由依据；
   强模型的分类结果会随供应商模型更新而漂移，且不可离线。
4. **glm-4.6 作为"强模型"的记录作废**，仅作为历史对照保留在下表（标注年份），不再作为结论依据。

| 意图引擎 | 准确率 | macro_recall | 延迟 p50 | 备注 |
|---|---|---|---|---|
| **bge large+base 原型集成** | **94.88%** | 93.83% | **390ms** | 零训练，213 条原型 |
| **bge-base 单模** | **92.93%** | 91.37% | **141ms** | 2G 内存形态 |
| qwen-max 零样本 | 88.05% | 81.89% | 562ms | 阿里云百炼（2026 年模型，接近前沿） |
| ~~glm-4.6 零样本~~ | ~~86.59%~~ | ~~77.81%~~ | ~~1094ms~~ | **作废：2025 年模型，不是前沿对照** |
| LLM 三路融合（旧基线） | 64.57% | — | 2047ms | glm-4-flash-250414 |

### 9.4 口径披露（防止误导）

- 本组是**零样本**对照：强模型未见过本任务类目微调；第 9.5 节另给了 few-shot 公平对照。
- 强模型输出经 JSON 解析 + 类目名兜底提取；解析失败计为错误（本次全量 0 失败）。
- 标签仍为 AI 自标注，人工盲测仍未完成（见第 7 节与 `benchmarks/intent/blind_sample.json`）。
- 两个强模型均通过 Anthropic 兼容端点接入，`temperature=0.0`，并显式关闭思考块
  （否则思考会吃光输出预算导致空回答，见 `core/llm_params.py` 的记录）。

## 9.5 few-shot 公平对照（2026-10-26 补齐，n=200 分层抽样）

上一节的零样本对照对 LLM 不公平：bge 用了 213 条领域原型，LLM 只有一行类目定义。
本组给强模型**每类 3 条原型示例**（示例取自 dev 集，绝不取自被测集，避免泄漏）。

| 方案 | 准确率 | prompt token | p50 延迟 |
|---|---|---|---|
| bge 原型集成 | **94.50%** | **0** | **125ms** |
| 强模型 zero-shot | 88.50% | 373 | 2250ms |
| 强模型 few-shot（3/类） | 92.00% | 1128 | 2313ms |

**结论**：
1. few-shot 把强模型从 88.5% 拉到 92.0%（**+3.5pp**）——"强模型意图识别率足够"这个判断成立。
2. bge 仍高 **2.5pp**、**零 token**、**快 18 倍**。意图在关键路径上，这个差距直接变成用户等待。
3. 因此保留意图层的理由不是"准确率更高"，而是**确定性、可离线、不随供应商模型漂移**。

脚本：`benchmarks/intent/eval_fewshot_fair.py`

## 9.6 模型盲判（标签质量的第三方证据，2026-10-26）

**先明确口径：这是 model-as-blind-annotator，不是人工盲测。**
它证明"标签在另一个强模型看来也成立"，**不能**证明"标签符合人类专家判断"。

做法：让一个从未见过答案 key 的前沿模型（DeepSeek-V4.1-Flash）独立判定
`blind_sample.json` 的 50 条，再与 key 比对。prompt 里只给文本与 19 类菜单。

| 分层 | 一致 | 比率 |
|---|---|---|
| canonical（规范表述） | 18/18 | **100%** |
| paraphrase（口语改写） | 15/15 | **100%** |
| near_miss（易混边界） | 13/17 | **76.5%** |
| **合计** | **46/50** | **92.0%** |

**4 条不一致，其中 3 条是 key 本身有争议（需人工优先复核）**：

| 文本 | key | 盲判 | 判断 |
|---|---|---|---|
| 几点了 | `other` | `general_consult` | key 可疑：纯闲聊归 other 合理，但归 general_consult 也说得通 |
| 满分回答 | `feedback` | `other` | key 可疑：无上下文时"满分回答"确实更像无语义输入 |
| 隐患排查和标准化考核是什么关系？ | `hazard_inspection` | `general_consult` | 边界题：跨两个类目，key 可辩护 |
| 国家对你们这类危化品的储存标准是怎么规定的？ | `chemical_safety` | `regulation_query` | 边界题：既是化学品也是法规条文，确实易混 |

**这条证据的价值**：它把"标签可能有噪声"从一句自我声明，变成了**可逐条核对的清单**。
人工只需复核这 4 条（而不是 50 条），复核成本从 50 降到 4。

脚本：`benchmarks/intent/blind_model_annotate.py`
产物：`benchmarks/intent/results/blind_model_trae-deepseek-v4.1-flash.json`
