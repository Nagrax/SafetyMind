## 4. 资料获取路线

### 4.1 先导出目录，再分批取得原件

1. 确认当前客户端的目标AppID、版本、正常会话和同步时间；优先导出其已可见的目录/Storage值。不读取微信私聊或凭证数据库，不操作其他小程序。
2. 保存完整原始目录快照与标准化manifest，至少含来源条目ID、标题、分类、更新时间、简介、网盘供应商、受控链接引用和导出时间。普通资料以 `downloadUrl` 为外链来源；批量导出字段不等于下载文件。
3. 同一个分享/文件夹只遍历一次；区分目录项、唯一分享、远端文件、压缩包内文件及内容去重后的原件。一个条目可能装很多文件，也可能与其他条目重复。
4. 优先读取远端大小、格式和文件夹清单，估算全量磁盘需求。先取得80份试点，再持续分批归档所有正常可取得的相关资料。
5. 失效、无关、重复、访问受限、解析失败和容量不足逐项保留。不得从分母删除失败项使覆盖率变好。

默认下载方案：**正常打开分享 → 按需在现有账号转存 → 官方客户端按清单下载至D盘 → 校验大小/格式/完整SHA-256 → 登记资产**。夸克官方说明支持文件/文件夹下载、暂停继续及并行任务数设置，可作为首轮通道；具体账户、分享和限制需实测。[官方下载说明](https://www.quark.cn/documents/help/fast-download)

外链是必要采集链路，不能因页面写“可选”而跳过。80份试点先选5～10个不同条目及其分享，核对是单文件、文件夹还是合集、是否多条复用同一链接、标题与实际文件如何对应；随后完成80份真实原件试点。用户图中的 `.ppt` 还提示需支持旧Office格式：按真实文件签名识别PPT/PPTX，旧PPT在D盘受控临时目录使用可用转换工具转为可解析格式，或保留明确的待转换状态；不能直接把PPTX解析器当成已支持PPT。

初始并行下载2个任务。正常可直接下载的分享无需额外转存；转存需要的网盘空间单独核算。不预先逆向夸克桌面协议，不把未经验证的私有API作为项目依赖；正常会话自动化确有必要时，封装小范围适配器并记录失败条件。

不将短期下载地址作为知识库资产ID，不把Cookie、token、提取码写进Git、报告、评测或模型上下文。公开manifest用 `source_link_ref`，必要访问值另存受控本地配置。下载、缓存和临时目录均在D盘。

### 4.2 如何决定哪些内容进入检索

全量登记目录，不预设“只有台账相关才有用”。依据真实目录和主题分布归类：法规规范、制度管理、操作技术、培训教材、事故/应急案例、MSDS、模板表单及其他。

- 可正常获取且相关的文本/Office原件：分批归档，合格正文进入检索。
- 失效规范、旧版本：保留历史用途和替代关系，回答现行要求时排除；版本未知不能伪称现行。
- 重复或近似资料：精确哈希去重，近似仅分组，保留差异版本。
- 扫描件、复杂表格：先质量检查，按缺口安排OCR；低质量不进入可靠证据集合。
- 视频/纯展示图片/超大包：目录全保留；按学习任务价值和容量决定获取/转写顺序，列为分层处理，不悄悄从全量范围消失。全文音视频处理属于可选深化，范围依据明确保留。
- 任何超出本次相关学习内容的文件：留下排除规则和逐项理由，不能只为节省工作量排除。

## 5. 装入agent的架构

资料根目录建议 `D:/SafetyMindData/corpus/`，大文件与代码分离。以下为拟建目录，不代表已经实现：

```text
D:/SafetyMindData/corpus/
  manifest.sqlite         来源/资产/版本/定位/FTS/状态
  originals/sha256/        完整原件，内容去重
  normalized/             完整段落、页、表格、OCR结果
  templates/              原模板与字段schema
  indexes/<build_id>/      短目录卡、精选正文向量
  staging/                未完成下载、解压、解析
  reports/                覆盖、容量、质量、效果与阻塞
  exports/<scope>/        用户私有学习产物
```

| 层 | 保存什么 | 如何使用 |
|---|---|---|
| 原件 | PDF/DOCX/XLSX/PPTX/压缩包等 | 磁盘保存，预览、下载、重解析时读取。 |
| 正文与表格 | 完整文字、页码、章节、sheet、单元格和来源 | 按定位读取，不让整份长文常驻prompt。 |
| 模板 | 原模板、字段、单位、必填项、表头和说明 | 模板搜索/解释字段；后续填表复用结构。 |
| FTS | 全部合格正文与表头的中文词面索引 | 查专业词、标准号、CAS、模板名与长尾内容。 |
| 向量 | 短目录卡+精选正文块 | 语义召回；控制激活规模和内存。 |
| 用户事实 | 用户自行输入的企业/学习场景信息 | 与公共示例分开，按主体访问范围隔离。 |

最低契约：来源 `provider/item_id/link_ref/exported_at`，另存 `share_id/share_file_id/entry_asset_mapping/mapping_status`；资产 `asset_id/sha256/mime/bytes/path/acquisition_status/parse_status`；版本 `logical_doc_id/version_id/source_id/title/category/industry/region/status/effective_from/effective_to`；正文 `block_id/version_id/content/locator/token_count/evidence_kind`；模板 `template_id/version_id/schema/asset_id`。

未知字段保留unknown。上传日期不是实施日期。文档ID不能只按title生成；“安全检查表”“应急预案”等同名不同源/版必须共存。版本改变重建对应索引，保留原件和来源；用户自有资料不能被同名百宝箱条目覆盖。

### 5.1 解析而非直接扁平化

- DOCX保留段落、表格、合并关系、签字栏和说明；`python-docx`可处理现有文档，但复杂对象与版式须样本验证。[官方文档](https://python-docx.readthedocs.io/en/latest/user/quickstart.html)
- XLSX保留sheet、行列、表头、单位、公式与合并单元格；抽取可使用openpyxl只读模式控制内存，写回模板需另行验证保真。[优化模式](https://openpyxl.readthedocs.io/en/stable/optimized.html)
- PDF逐页提取；扫描页按需OCR，表格保留表头与行值联系；关键数字/单位/条件可回看原页。
- PPT/PPTX保留页码、页内文字与注释；先识别真实格式，旧PPT按受控转换路径处理，转换后保留原件哈希、工具版本和页数对照。案例、培训材料提取事实与结构，不能编造伤亡数字或案例结论。
- MSDS按名称/CAS/产品/厂商/日期及原章节组织；若来源有16段则保留对应结构，不把不同产品版本拼成一份“标准MSDS”。
- 压缩包先清点成员与解压大小，限制受控目录和体积；不执行宏或附件程序。
- 每份记录解析工具版本、页/sheet数、错误与质量状态；保留完整正文，不能以截取前6000字代替归档。
- 法规/标准的状态核验优先官方来源；现行、即将实施、被替代、废止分别管理，不凭文件名年份推断。[法律法规数据库](https://flk.npc.gov.cn/search)、[国家标准全文公开系统](https://openstd.samr.gov.cn/)

### 5.2 检索流程

```text
学习需求 → 任务/主题/访问范围/用途与版本条件
         → 各通道先过滤再召回：全文FTS + 短目录卡 + 精选正文向量
         → RRF融合/去重 → 按定位读取实际正文或表格并复核范围
         → 少量证据进入模型 → 有出处回答/原件/模板
```

复用当前 `BAAI/bge-base-zh-v1.5`，实际768维；模型进程内已共享，多worker仍可能复制。正式记录模型版本、维数、池化、归一化、查询前缀与分块版本；文档与查询必须使用同一配置，服务器模式也不能依赖未核验的默认嵌入器。

所有符合检索条件的文档先建一张短目录卡，卡从标题、目录、字段和已解析正文确定性生成，标记 `evidence_kind=catalog`。卡与正文分两个集合；命中卡后必须回取实际正文，不拿目录摘要当规范条文。

正文向量先80份，后至多300份，且**不超过30000块，两个上限先到哪个就停止扩激活**。未精选的合格正文仍由FTS独立召回，再按需读章节；卡不覆盖长文全部主题，不宣称实现全量正文语义检索。

FTS5采用中文预分词+BM25；标准号、CAS等独立精确字段。unicode61本身不是中文分词器，trigram也不能独立解决所有二字词。初始各路前20候选，RRF常数60，去重后至多32正文块轻量复排；不另加载重排模型，不默认加LLM查询改写/重排成本。

当前嵌入max_length=256；正文目标约180～220 token并预留标题/特殊token，实际以tokenizer计数。超长句需硬切；表格按行组附表头。按block定位取邻块，避免读全部兄弟子块。每次资料上下文起始预算3000～5000 token并服从模型总上下文预算，工具返回与模板字段一起计入。

| 2640份×80块 | 211200 | 618.75MiB | 825.00MiB |

| 项目 | 初始预算/约束 | 超限处理 |
|---|---|---|
| 原件 | 8GiB | 保留待下载文件与大小，列容量阻塞；不能把剩余项改done。 |
| 规范化正文+FTS | 1GiB | 在总预算内按实测调配，不能静默丢正文。 |
| 索引与旧构建快照 | 1GiB | 小批构建和切换；保留回滚能力。 |
| 临时下载/解压/解析 | 1GiB | 受控单批，及时释放本次临时文件；大包不盲目解压。 |
| 总磁盘 | 初始11GiB，且D盘始终保留≥15GiB | 两者任一触发即暂停扩大落盘；计入副本、旧索引、未完成下载和导出。 |
| 在线新增RSS | 同负载相对基线，相关进程汇总增量目标≤512MiB | 降低激活/候选规模或回FTS；不能通过拆进程漏计内存。 |
| 系统可用RAM | <1.5GiB停扩激活，<1GiB停后台解析/建库 | 保存检查点，不强行并发。 |

分别测在线暖机稳态与构建/OCR峰值，汇总API、Chroma、解析和worker；若模型尚未加载，冷启动新增峰值另报，不能隐去。512MiB是待验证目标，不是已达到的性能。

**必须修复批量缓存放大：**当前BGE LRU的1024项按调用批次计数，键包含整批文本，值保留整批Python浮点列表；不等于仅1024个float32向量。建库绕过在线查询缓存，查询缓存按字节/向量数限额并加回归。当前Chroma锁定1.5.9，不照搬旧版内部LRU或假定某环境变量可强制限制RSS。

优先用远端完整文件大小估算容量；缺失时按80份格式/类别样本外推，纳入解压、索引与版本副本。吞吐、下载速度、OCR耗时分别实测后估算工期，不提前承诺全量需几小时或几天。
